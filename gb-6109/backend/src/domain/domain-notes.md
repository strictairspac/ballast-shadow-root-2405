# 磨料试配签发与页发布

岑砾道料的 8 人小组过去用打印稿追踪三条道砟筛配配方。断电后无法从旧纸面判断生效版，重试容易耗掉仅剩的页空间，留档配方页也可能被过早覆盖。上游是筛配试验员提交的粗料与细料基点，下游是生产签发主管。基点总和固定为 10000。

13:00 留存 BR-051–053 基准；13:10 将 BR-051 细料调至 2700 基点、BR-052 调至 3200；13:15 在影子页刷盘后、换根前模拟断电；13:20 复启保持旧根并重试；13:25 BR-053 改到 3100 时触发 5 页预算；13:30 解封基准；13:35 再试成功；13:40 导出新根配方和复用证据。

每张配方映射到独立物理页。写时复制为改动配方分配未引用页，根发布成功后，能回收未被当前根或封存根引用的旧页。演练将根指针切换视为原子动作，无 WAL 重做、持久存储刷盘或 PostgreSQL 内核修改；数据库保存输入、任务和回执。页数统计不含根元数据。

## 共享复演页池（shared_pool）

多张配方签发单（批次）共用一份物理页额，对应代码：

- `pool.py`：线程安全的 `SharedPagePool`，所有状态在同一把锁内变更；提供非阻塞 `request`、阻塞 `acquire`、`release`、`pump` 与统一事件流。
- `pool_scenario.py`：按虚拟节拍确定性重放批次的到达、等待、领页、断电中断、续跑与归还，输出时间线 `rows`、批次台账 `batches` 和指标。

调度口径：

1. 领页按整批峰值一次性预留，做完才整笔归还，一个批次只还一次。
2. 单批峰值超过页池总额直接退回，不占任何页额；任意时刻 `reserved <= capacity`。
3. 页不够进 FIFO 队列；队头让行未达上限时，后面额度够用的小单可越过它先跑，每越过一次队头 `overtaken` 加一。
4. 队头 `overtaken` 达到让行上限（默认 2）即成为队列屏障，队列整体卡到它领页为止，杜绝大单被无限插队。
5. 断电回收前暂占页仍计入总额；续跑沿用同一笔预留，不重新领页、不重复计数。

输入以 `mode=shared_pool` 标识，`batches` 每项含 `id`、`peak`、`duration`、`arrival`，可选 `interrupt.after` 与 `interrupt.resume_after`；页池总额取批次提交参数（1–128）。
